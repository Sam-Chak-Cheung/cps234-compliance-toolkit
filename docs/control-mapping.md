# CPS 234 Control Mapping

| CPS 234 Area | Example Control Domains | Evidence Examples | Review Frequency |
| --- | --- | --- | --- |
| Information security capability | Security strategy, operating model, resourcing, threat intelligence | Strategy documents, role descriptions, capability assessments | Annual or material change |
| Policy framework | Policies, standards, procedures, exceptions | Approved policy set, review records, exception register | Annual |
| Information asset identification | Asset inventory, classification, ownership | CMDB, data register, cloud inventory, service owner list | Quarterly |
| Control implementation | IAM, network security, endpoint security, logging, vulnerability management | Configuration exports, dashboards, tickets, architecture diagrams | Monthly to quarterly |
| Testing control effectiveness | Control testing, audits, penetration testing, tabletop exercises | Test plans, results, remediation tracking | Risk-based |
| Incident management | Detection, escalation, response, lessons learned | Incident records, playbooks, post-incident reviews | After each material incident |
| Notification obligations | Regulatory escalation, decision records, communications | Notification procedure, APRA assessment records | Annual and after incidents |
| Third-party security | Due diligence, contracts, assurance, monitoring | Vendor assessments, SOC reports, contractual clauses | Annual or renewal |

## Practical Use

Use this mapping as a starting point for workshops, gap assessments, and evidence collection. Tailor control domains and evidence expectations to the organisation's risk profile, materiality, and operating model.
